接口文档
地址
POST {{.APIBase}}<主题标识>
Authorization: Bearer <key>

key 只能放在请求头里，不支持放在网址参数里（会进访问日志）。key 和主题标识必须对应。

请求体

Content-Type: application/json 时按下表读字段；其他类型（如 curl -d 默认的表单类型、text/plain）整个请求体当作正文。请求体最大 64KB。

字段必填说明
message是正文，最多 4000 字；超过推送服务单条上限的部分会截断
title否标题，最多 100 字。通知显示为「图标 [主题名] 标题」，不传只显示「图标 [主题名]」
priority否通知等级 1–5（最低 / 低 / 普通 / 高 / 紧急），不传用推送账号的默认通知等级。4、5 响铃弹出（仅 ntfy）；按账号发送策略里该等级设的遍数连发
click否点通知打开的网址，只能是 http / https（仅 ntfy）
tags否附加标签，最多 3 个，每个 1–20 字。主题标识总会作为第一个标签（仅 ntfy）
示例
curl -H "Authorization: Bearer <key>" -d "有新的问卷提交" {{.APIBase}}survey

curl -H "Authorization: Bearer <key>" -H "Content-Type: application/json" \
  -d '{"title":"新问卷","message":"张三提交了满意度问卷","priority":4,"click":"https://example.com/s/123"}' \
  {{.APIBase}}survey
返回
状态码说明
202{"ok":true,"id":123} 已进推送队列，通常一秒内送达；失败会自动重试（最多 8 次，间隔逐步拉长到 1 小时）
400参数错误，error 里有原因
401key 无效，或 key 和主题标识不对应
403主题已停用
409推送账号的 ntfy / Bark 都已停用
413请求体超过 64KB
429每个主题每分钟最多 60 次；同一 IP 10 分钟内 key 错 10 次会被暂时拒绝。按 Retry-After（秒）等待后重试
503推送队列积压过多，稍后重试

出错时返回 {"ok":false,"error":"原因"}。正文和标题不落库，只在推送前存在内存里；服务重启时还没推出去的会丢失，记录里显示失败。
